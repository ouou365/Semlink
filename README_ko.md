## 🤔 왜 Semlink인가?

당신은 수년간 글을 써 왔습니다. 그런데 자신의 지식에 대해 질문하려면 흐름은 이렇습니다: 어느 폴더였는지 기억해 내고, Ctrl+F 하고, 채팅 창에 복사-붙여넣기하고, 맥락은 놓쳐 버립니다.

다른 Obsidian AI 플러그인도 노트와 채팅은 해 줍니다. 그러나 보여 주지 않는 것은 '작업 과정'입니다. 대부분의 RAG 플러그인은 블랙박스 안에서 몇 개의 청크를 검색한 뒤 어쨌든 답합니다 — 청크는 틀렸어도 어조만은 확신에 차 있습니다. Smart Connections는 관련 노트를 찾아 주지만 정작 답은 하지 않습니다. Omnisearch는 키워드에서 멈춥니다. 그리고 '진지한' 길 — 노트를 ChatGPT에 붙여넣거나 터미널에서 Claude Code를 구동하는 것 — 은 당신의 지식이 에디터 밖 어딘가에 살게 됨을 의미합니다.

Semlink는 거꾸로 만들어졌습니다:

**에이전트가 당신의 Vault 안에 살고 — 당신은 그 일하는 모습을 지켜봅니다.** 모든 답변에는 모델의 생각 과정, 호출한 모든 도구(`search_notes` → `get_note` → …), 그리고 당신의 노트로 되돌아가는 번호 매기기 인용이 함께합니다. 답변을 무조건 믿을 필요 없습니다. 직접 검증하면 됩니다.

### 일부러 내린 세 가지 선택

🗄️ **로컬 퍼스트, 구조적으로.** 인덱스는 당신 디스크의 SQLite 파일입니다. Semlink 서버라는 것이 존재하지 않습니다 — '노트를 올리지 않겠다고 약속한다'가 아니라, 애초에 올릴 곳이 없습니다.

🔌 **이미 결제 중인 모델이면 무엇이든.** DeepSeek, GLM, SiliconFlow, OpenAI, Claude, Ollama, LM Studio — OpenAI 또는 Anthropic 호환 엔드포인트라면 무엇이든. Semlink는 마진을 붙이지 않고 토큰에 손대지도 않습니다. 사용량은 제공자가 당신에게 직접 청구합니다.

🪟 **Vault의 원주민.** 노트를 채팅으로 끌어다 놓아 첨부하고, 답변을 노트로 되돌려 저장하고, 컨텍스트 링이 실시간으로 차오르는 걸 지켜보세요. 타이핑하는 동안 인덱싱은 길을 비켜 줍니다. 에이전트는 노트가 이미 살고 있는 곳에서 일합니다 — 내보낼 것도, 동기화할 것도 없습니다.

## 🎯 나에게 맞을까?

**✅ 이렇다면 적합합니다:**

- 몇 달(혹은 몇 년)치 노트가 쌓여 있고, 평범한 말로 노트에 *질문*하고 싶다
- 검증할 수 있는 추론 — 생각 과정, 도구 호출, 인용 — 을 원하고, 확신에 찬 블랙박스는 원하지 않는다
- 노트가 절대 내 컴퓨터를 떠나지 않는 것이 중요하다
- 이미 LLM API key가 있거나(또는 로컬 모델을 돌리고) 중간마진이 못마땅하다
- Claude Desktop, Claude Code 또는 Cursor를 쓰며, 그들도 내 Vault를 읽기를 원한다

**❌ 이렇다면 맞지 않습니다:**

- ChatGPT의 범용 대체품을 원한다 — Semlink는 인터넷이 아니라 당신의 Vault에서 답합니다
- 설정 없이 바로 쓰길 기대한다 — 임베딩 API key와 채팅 모델 key가 필요합니다(무료 플랜으로도 충분합니다)
- 팀 협업이나 클라우드 동기화가 필요하다 — 설계상 백엔드가 없습니다

## 🚀 빠른 시작

1. **설치** — Obsidian 설정 → 커뮤니티 플러그인에서 "Semlink"를 검색해 한 번에 설치하거나, [플러그인 페이지](https://community.obsidian.md/plugins/semlink)에서 직접 설치하세요.
2. **설정** — 임베딩 API key(SiliconFlow BGE-M3 사전 구성됨)와 채팅 제공자 key를 붙여넣습니다. 3단계 온보딩이 둘 다 검증하고 인덱싱을 시작합니다.
3. **질문.** 사이드바를 열고: *"Zettelkasten에 대해 뭘 썼더라?"* — 그리고 지켜보세요: 생각 → `search_notes` → `get_note` → [1][2][3]이 달린 답변.

이게 전부입니다. 노트는 절대 수정되지 않습니다 — Semlink는 읽기만 합니다.

## ✨ 기능

### 🕵️ 챗봇이 아니라, 도구를 쓰는 에이전트

내장 도구 아홉 개 — 의미 검색, 노트 읽기, 섹션 읽기, 유사 노트, regex grep, 인덱스 나열(타임스탬프 포함), 현재 노트 인식 — 답변하는 동안 모델이 무엇을 가져올지 스스로 결정합니다. 청크 세 개를 긁어와 그 위에 지어내는 게 아니라, 검색하고, 알맞은 섹션을 읽고, 모든 단계를 보여 줍니다.

### 🔍 모든 것에 닿는 의미 검색

키워드가 아니라 의미로 질의합니다 — 자연어 질의 하나로 지금까지 쓴 모든 노트에 닿습니다. *정확한* 문자열을 알고 있을 때를 위한 유사 노트 추천과 regex grep도 준비되어 있습니다.

### 🪟 Vault의 원주민

- **드래그 & 드롭**: 패널 어디든 노트를 놓으면 첨부됩니다 — `[[위키 링크]]`가 인라인으로 해석됩니다
- **답변을 노트로 저장**: 클릭 한 번으로 Vault에 되돌려 저장합니다
- **눈에 보이는 컨텍스트**: 실시간 컨텍스트 링이 모델 윈도우의 사용량을 보여 주고, 옆에는 캐시 적중률이 표시됩니다 — 답변이 얕아졌을 때 모델 탓하기 전에 원인을 먼저 알 수 있습니다
- **홈 질문 카드**: 엄선된 예시 프롬프트, 일부는 당신의 최근 노트에서 뽑습니다

### ⚡ 실시간 인덱싱

파일 변경이 자동으로 감지되어 쓰는 즉시 재임베딩됩니다 — 작업 중일 때는 인덱싱이 길을 비켜 주므로 에디터는 끊기지 않습니다.

## 🤖 모델은 내 것으로

OpenAI 호환 또는 Anthropic 호환 엔드포인트라면 무엇이든 됩니다: DeepSeek(사전 구성됨), SiliconFlow, GLM, OpenAI, Anthropic, Ollama, LM Studio, OpenRouter — 당신의 key, 당신의 요금, 무제한 전환. 중요한 것은:

- **채팅 모델**: 긴 컨텍스트가 유리합니다 — 답변이 노트를 대량으로 인용합니다
- **임베딩 모델**: BGE-M3(1024차원)가 SiliconFlow로 사전 구성됨. 호환 임베딩 엔드포인트라면 무엇이든 됩니다
- 모델 사용량은 제공자가 청구합니다 — Semlink는 한 푼도 볼 일이 없습니다

## 🌐 MCP — 다른 AI에게도 기억을

같은 도구가 로컬 MCP 서버로도 제공되어 Claude Desktop, Claude Code, Cursor도 당신의 Vault를 검색하고 인용할 수 있습니다:

```json
{ "mcpServers": { "semlink": { "type": "http", "url": "http://127.0.0.1:3001/mcp" } } }
```

localhost 전용, 선택적 access key. 클라우드 중계 없음.

## ❓ FAQ

**내 데이터는 어디론가 전송되나요?**
인덱스는 당신 디스크의 플러그인 폴더 안 `data/`에 살습니다. 네트워크 호출은 *당신이* 구성한 제공자로만 향합니다. 자세한 내용은 [개인정보 처리방침](https://getsemlink.com/privacy.html)을 참고하세요.

**Copilot for Obsidian과 뭐가 다른가요?**
투명성과 에이전트 루프입니다: 생각 과정과 모든 도구 호출이 보이고, 모델이 어떤 노트를 읽을지 스스로 고르며, 답변은 열어볼 수 있는 구체적 노트를 인용합니다. Copilot으로 충분하다면 그대로 두세요 — Semlink는 작업 과정을 지켜보고 싶을 때를 위한 것입니다.

**API key가 필요한가요?**
네 — Semlink는 설계상 BYOK입니다. 무료 플랜(SiliconFlow, Groq…)으로도 임베딩과 채팅 모두 충분합니다.

**인덱스는 어디에 저장되나요?**
플러그인 폴더 안의 `data/vault.db`(SQLite)와 `data/vectors.bin`입니다. 언제든 지우고 재인덱싱할 수 있습니다. 어떤 것도 당신의 컴퓨터를 떠나지 않습니다.

**어떤 모델을 써야 하나요?**
긴 컨텍스트를 지원하는 마음에 드는 채팅 모델이면 무엇이든 — 답변이 노트를 대량으로 인용합니다. 임베딩은 저렴하고 드물게 발생합니다(BGE-M3).
