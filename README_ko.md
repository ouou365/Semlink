# 🧠 Semlink — 에이전틱 지식 워크스페이스 (Agentic Knowledge Workspace)

**당신의 Obsidian Vault가 생각하고, 협력하고, 행동하게 하세요.**

**한국어** | [English](README.md) | [简体中文](README_CN.md) | [繁體中文](README_zh-Hant.md) | [日本語](README_ja.md) | [Deutsch](README_de.md) | [Français](README_fr.md) | [Español](README_es.md) | [Português](README_pt.md) | [Italiano](README_it.md) | [Русский](README_ru.md)

Semlink는 Obsidian Vault를 에이전틱 지식 워크스페이스로 바꿉니다 — 사이드바에 살면서 지금까지 적어 온 모든 것을 검색하고, 진짜 도구로 추론하고, 모든 주장을 당신의 노트로 인용하고, 배운 것을 공유하는 AI 어시스턴트입니다. 에이전트 전체가 플러그인 안에 담겨 있습니다: Claude Desktop도, Cursor도, 터미널도, 설치할 서드파티 클라이언트도 필요 없습니다. 자신의 API key를 가져오면, Vault가 생각하기 시작합니다.

## 🤔 왜 Semlink인가?

당신은 수년간 글을 써 왔습니다. 그런데 자신의 지식에 대해 질문하려면 흐름은 이렇습니다: 어느 폴더였는지 기억해 내고, Ctrl+F 하고, 채팅 창에 복사-붙여넣기하고, 맥락은 놓쳐 버립니다.

대부분의 Obsidian AI 플러그인은 서드파티 에이전트 클라이언트에 의존합니다 — 그리고 그 클라이언트는 프로그래밍용으로 만들어진 에이전트 애플리케이션입니다. 그래서 당신에게 오는 것은 노트에 잠깐 들르는 코딩 어시스턴트이지, 노트 안에서 실제로 일하는 에이전트가 아닙니다.

Semlink는 거꾸로 만들어졌습니다:

**워크스페이스는 Vault이고, 에이전트는 내장되어 있습니다 — 나중에 덧붙인 것이 아니라.** 플러그인을 설치하고, key를 붙여넣고, 질문하세요. 에이전트는 생각하고, 도구를 호출하고, 노트를 읽고, 번호 매기기 인용과 함께 답합니다 — 전부 Obsidian 안에서 이루어집니다. 답변을 맹신할 필요는 없습니다. 만들어지는 과정을 지켜본 뒤 직접 검증하면 됩니다.

### Semlink vs. Copilot for Obsidian

| | Semlink | Copilot for Obsidian |
|---|---|---|
| 외부 도구 불필요 | ✅ 에이전트, RAG, 공유 모두 플러그인에 내장 | ❌ 에이전트에 opencode 필요, RAG에 Miyo 필요 — 별도 설치 |
| 에이전트 루프(검색 → 읽기 → 추론) | ✅ 9개 도구, 읽을 내용은 모델이 결정 | 🟡 외부 클라이언트 경유 |
| 추론 투명성 | ✅ 생각 + 도구 추적, 플러그인 안에서 실시간 스트리밍 | 🟡 루프가 Obsidian 밖에서 실행됨 |
| 인용 | ✅ 턴마다 하나의 번호 매기기 레지스트리; 인용 클릭 시 출처 노트로 바로 이동 | 🟡 출처 노트 나열됨 |
| 답변 공유 | ✅ LAN 웹 페이지 + QR 코드, 언제든 취소 | ❌ 복사-붙여넣기 |
| 다른 AI도 Vault를 읽음(MCP) | ✅ 로컬 서버 내장 | ❌ |

### 일부러 내린 선택

🧠 **에이전트는 방문자가 아니라 거주자입니다.** 에이전트에 필요한 모든 것 — 검색, 도구, 생각 추적, 인용, 공유 — 이 플러그인 안에 담겨 있습니다. 외부 AI 클라이언트도 MCP를 통해 환영하지만, 어디까지나 선택적 보너스이지 전제 조건이 결코 아닙니다.

🗄️ **로컬 퍼스트, 구조적으로.** 인덱스는 당신 디스크의 SQLite 파일입니다. Semlink 서버라는 것이 존재하지 않습니다 — '노트를 올리지 않겠다고 약속한다'가 아니라, 애초에 올릴 곳이 없습니다.

🔑 **BYOK, 추측 없이.** 24개 채팅 제공자 카탈로그(가격과 컨텍스트 윈도우가 표시된 1,800개 이상 모델)와 전용 임베딩 제공자 카탈로그가 클릭 몇 번으로 설정을 끝내 줍니다; Ollama 같은 로컬 런타임은 key가 전혀 없어도 동작합니다. Semlink는 마진을 붙이지 않고 토큰에 손대지도 않습니다 — 사용량은 제공자가 당신에게 직접 청구합니다.

🪟 **Vault의 원주민.** 노트를 채팅으로 끌어다 놓아 첨부하고, 답변을 노트로 되돌려 저장하고, 컨텍스트 링이 실시간으로 차오르는 걸 지켜보세요. 타이핑하는 동안 인덱싱은 길을 비켜 줍니다. 워크스페이스는 노트가 이미 살고 있는 곳에 삽니다 — 내보낼 것도, 동기화할 것도 없습니다.

## ✨ 핵심 기능

### 🔗 실제로 따라갈 수 있는 인용

모든 턴은 생각 추적, 답변 본문, 출처 카드에 걸쳐 하나의 번호 매기기 레지스트리를 사용합니다 — 답변 속의 `[3]`은 당신이 모델이 읽는 걸 지켜본 바로 그 `[3]`입니다. 인용을 클릭하면 Obsidian이 해당 노트의 정확히 그 지점을 엽니다. 답변은 대조 검증할 수 있는 노트만큼만 좋습니다 — 그러니 검증하세요.

### 📡 아무것도 내보내지 않고 답변 공유하기

보여 줄 만한 것을 찾았나요? 클릭 한 번으로 질문, 생각 추적, 답변, 출처 카드 — 주고받은 전부 — 를 LAN 위의 깔끔한 웹 페이지로 게시합니다. 링크나 QR 코드를 보내면 읽는 사람은 어떤 브라우저에서든 엽니다 — Obsidian도, 계정도, 설치도 필요 없습니다. 공유를 중지하면 페이지는 사라집니다. 어떤 것도 당신의 네트워크를 떠나지 않습니다.

### 🪟 에이전트가 일하는 모습을 실시간으로 지켜보기

출력은 답변만이 아닙니다 — 추론 과정도 출력입니다. 생각은 그려지는 대로 스트리밍되고, 모든 도구 호출(`search_notes` → `get_section` → …)은 결과와 함께 기록되며, 컨텍스트 링은 캐시 적중률을 포함해 모델 윈도우가 얼마나 찼는지 보여 줍니다. 모델이 본 것을 정확히 보게 됩니다 — 그것이 핵심입니다.

## 🚀 빠른 시작

1. **설치** — [플러그인 페이지](https://community.obsidian.md/plugins/semlink)에서 클릭 한 번으로 설치하거나, 설정 → 커뮤니티 플러그인에서 "Semlink"를 검색하세요.
2. **설정** — 카탈로그에서 제공자를 고르고(또는 커스텀 엔드포인트를 붙여넣고) API key를 추가하세요. 3단계 온보딩이 채팅 + 임베딩을 검증하고 인덱싱을 시작합니다.
3. **질문.** 사이드바를 열고: *"Zettelkasten에 대해 뭘 썼더라?"* — 그리고 지켜보세요: 생각 → `search_notes` → `get_note` → [1][2][3]이 달린 답변.

이게 전부입니다. 에이전트 클라이언트도, 서버 설정도 없습니다. 노트는 절대 수정되지 않습니다 — Semlink는 읽기만 합니다.

## 🧠 생각 — 과정을 보여 주는 에이전트

- **내장 도구 아홉 개** — 답변하는 동안 무엇을 가져올지는 모델이 스스로 결정합니다: 의미 검색, 노트 읽기, 섹션 읽기, 유사 노트, regex grep, 타임스탬프가 붙은 인덱스 나열, 현재 노트 인식. 청크 세 개를 긁어와 그 위에 지어내는 법이 없습니다; 검색하고, 알맞은 섹션을 읽고, 모든 단계를 보여 줍니다.
- **들여다볼 수 있는 생각.** 모든 답변에는 모델의 추론과 도구 호출 하나하나(`search_notes` → `get_section` → …)가 실시간으로 스트리밍되어 따라옵니다 — 확신에 찬 블랙박스가 아닙니다.
- **검증되는 인용.** 턴마다 하나의 번호 매기기 레지스트리가 생각 추적, 답변 본문, 출처 카드를 관통합니다; 인용을 클릭하면 출처 노트(와 줄)로 바로 이동합니다.
- **모든 것에 닿는 검색**: 지금까지 쓴 모든 노트를 의미로 질의합니다 — 유사 노트 추천과, 정확한 문자열을 *알고* 있을 때를 위한 regex grep도 함께입니다.

## 🤝 협업 — 사일로를 벗어나는 지식 (당신의 조건대로)

- **LAN에서 대화 공유**: 클릭 한 번으로 Q&A를 깔끔한 웹 페이지로 게시합니다 — 링크나 QR 코드를 보내면 읽는 사람이 어떤 브라우저에서든 열 수 있고, 공유는 언제든 취소할 수 있습니다. 어떤 것도 당신의 네트워크를 떠나지 않습니다.
- **답변은 노트가 됩니다**: 어떤 답변이든 클릭 한 번으로 Vault에 되돌려 저장합니다.
- **드래그 & 드롭으로 첨부**: 패널 어디든 노트를 놓으면 — `[[위키 링크]]`가 인라인으로 해석됩니다 — 에이전트가 그 노트부터 읽습니다.
- **선택 사항: 다른 AI도 들여오기.** 같은 도구가 로컬 MCP 서버로도 제공되어 Claude Desktop, Claude Code, Cursor도 당신의 Vault를 검색하고 인용할 수 있습니다. 어디까지나 선택 사항입니다 — 내장 에이전트는 도움이 필요 없습니다.

## ⚡ 행동 — 실시간 제어

- **진행 막대가 아니라 RAG 대시보드**: Vault 지표, 노트 단위의 실제 임베딩 진행 상황, 그리고 즉시 적용되는 인덱스 / 자동 임베딩 토글 — 실행 중에도 반영됩니다.
- **번거로움 없는 재설정**: 임베딩 모델을 바꾸면 전체 재인덱싱이 자동으로 시작됩니다; 가이드가 key를 다시 검증하고 알맞은 단계로 안내합니다.
- **실시간 인덱싱**이 쓰는 즉시 모든 파일 변경을 반영합니다 — 그리고 타이핑하는 동안은 길을 비켜 주므로 에디터가 결코 끊기지 않습니다.
- 인덱싱, MCP, 디버그 로깅, 진행 상황에 대한 **커맨드 팔레트 제어**.

## 🔑 BYOK — 자신의 key 가져오기

OpenAI 호환 또는 Anthropic 호환 엔드포인트라면 무엇이든 동작합니다 — DeepSeek, GLM, SiliconFlow, OpenAI, Anthropic, OpenRouter, Ollama, LM Studio, 그리고 내장 카탈로그에 담긴 1,800개 이상. 중요한 것은:

- **채팅 모델**: 가격과 컨텍스트 윈도우가 표시된 카탈로그에서 고르거나, 커스텀 엔드포인트를 추가하세요(key 없는 로컬 런타임 포함)
- **임베딩 모델**: 전용 임베딩 제공자 카탈로그 — SiliconFlow BGE-M3 사전 구성됨; Jina, Voyage, Nomic, Mixedbread 등, 또는 key 없는 로컬 임베딩 엔드포인트
- **당신의 key, 당신의 요금, 무제한 전환** — 모델 사용량은 제공자가 청구합니다; Semlink는 한 푼도 볼 일이 없습니다

## 🌐 MCP — 선택 사항, 다른 AI를 위해

내장 에이전트는 그 자체로 완결되어 있습니다. Claude Desktop, Claude Code 또는 Cursor도 함께 쓴다면, 같은 도구가 로컬 MCP 서버로 노출됩니다:

```json
{ "mcpServers": { "semlink": { "type": "http", "url": "http://127.0.0.1:3001/mcp" } } }
```

localhost 전용, 선택적 access key. 클라우드 중계 없음.

## ❓ FAQ

**Claude Desktop, Cursor 또는 다른 AI 클라이언트가 필요한가요?**
아니요. 완전한 에이전트 — 생각 추적, 도구 호출, 인용, 공유 — 는 플러그인 안에서 실행됩니다. MCP는 외부 AI가 Vault를 읽을 *수 있도록* 존재할 뿐, 반드시 그래야만 해서 존재하는 것이 아닙니다.

**내 데이터는 어디론가 전송되나요?**
인덱스는 당신 디스크의 플러그인 폴더 안 `data/`에 살고 있습니다. 네트워크 호출은 *당신이* 구성한 제공자로만 향합니다. LAN 공유는 당신의 네트워크 안에 머뭅니다. 자세한 내용은 [개인정보 처리방침](https://getsemlink.com/privacy.html)을 참고하세요.

**Copilot for Obsidian과 뭐가 다른가요?**
Copilot은 에이전트를 opencode로, RAG를 Miyo로 중계합니다 — 플러그인과 함께 설치하고 구동해야 하는 외부 도구들입니다. Semlink는 전체 루프를 Obsidian 안에 유지합니다: 생각과 모든 도구 호출이 보이고, 모델이 어떤 노트를 읽을지 고르며, 답변은 열어볼 수 있는 구체적 노트를 인용합니다. Copilot으로 충분하다면 그대로 두세요 — Semlink는 클라이언트를 더 늘리는 게 아니라 워크스페이스를 원할 때를 위한 것입니다.

**API key가 필요한가요?**
Semlink는 설계상 BYOK입니다 — 하지만 "자신의 key"에는 채팅과 임베딩 모두에 쓸 수 있는 Ollama 같은 key 없는 로컬 런타임도 포함됩니다. 클라우드 무료 플랜(SiliconFlow, Groq…)으로도 충분합니다.

**인덱스는 어디에 저장되나요?**
플러그인 폴더 안의 `data/vault.db`(SQLite)와 `data/vectors.bin`입니다. 언제든 지우고 재인덱싱할 수 있으며, 어떤 것도 당신의 컴퓨터를 떠나지 않습니다.

**어떤 모델을 써야 하나요?**
긴 컨텍스트를 지원하는 마음에 드는 채팅 모델이면 무엇이든 — 답변이 노트를 대량으로 인용합니다. 임베딩은 저렴하고 드물게 발생합니다(BGE-M3).
