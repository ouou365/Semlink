# 🧠 Semlink — エージェント知識ワークスペース（Agentic Knowledge Workspace）

**あなたの Obsidian Vault を、考え、協働し、行動させる。**

**日本語** | [English](README.md) | [简体中文](README_CN.md) | [繁體中文](README_zh-Hant.md) | [한국어](README_ko.md) | [Deutsch](README_de.md) | [Français](README_fr.md) | [Español](README_es.md) | [Português](README_pt.md) | [Italiano](README_it.md) | [Русский](README_ru.md)

Semlink はあなたの Obsidian Vault をエージェント知識ワークスペースへと変えます — サイドバーに住む AI アシスタントが、これまでに書いたすべてを検索し、本物のツールで推論し、すべての主張をノートへの引用で裏付け、学んだことを共有します。エージェントはまるごとプラグインの中に組み込まれています: Claude Desktop も、Cursor も、ターミナルも、サードパーティクライアントのインストールも不要。自分の APIキーを持ってくるだけで、Vault が考え始めます。

## 🤔 なぜ Semlink なのか？

何年も書きためてきたのに、いざ自分の知識について質問しようとすると、ワークフローはこうなります。どのフォルダだったか思い出して、Ctrl+F で検索し、チャットウィンドウにコピペして、そして迷子になる。

ほとんどの Obsidian AI プラグインはサードパーティのエージェントクライアントに依存しています — しかもそのクライアントは、プログラミング用に作られたエージェントアプリケーションです。手に入るのは「ノートに立ち寄るコーディングアシスタント」であって、ノートの中で実際に働くエージェントではありません。

Semlink は逆の発想で作られています:

**ワークスペースは Vault そのものであり、エージェントは最初から組み込まれています — 後付けではありません。** プラグインを入れ、キーを貼り、質問する。エージェントは考え、ツールを呼び出し、ノートを読み、番号付き引用つきで答えます — そのすべてが Obsidian の中で完結します。回答を鵜呑みにする必要はありません。作られる過程を見て、それから確認すればいいのです。

### Semlink vs. Copilot for Obsidian

| | Semlink | Copilot for Obsidian |
|---|---|---|
| 外部ツール不要 | ✅ エージェント・RAG・共有のすべてをプラグインに内蔵 | ❌ エージェントには opencode、RAG には Miyo が別途必要 |
| エージェントループ（検索 → 読取 → 推論） | ✅ 9 ツール、モデルが読むべきものを判断 | 🟡 外部クライアント経由で実行 |
| 推論の透明性 | ✅ 思考とツールの痕跡をプラグイン内でライブにストリーミング | 🟡 ループは Obsidian の外で動く |
| 引用 | ✅ ターンごとに 1 つの番号レジストリ。引用をクリックすると出どころのノートへジャンプ | 🟡 出典ノートを一覧表示 |
| 回答の共有 | ✅ LAN Web ページ + QR コード、いつでも取り消し可能 | ❌ コピペのみ |
| 他の AI が Vault を読める（MCP） | ✅ ローカルサーバーを内蔵 | ❌ |

### 意図して貫いた選択

🧠 **エージェントは訪問者ではなく住人。** エージェントに必要なもの — 検索、ツール、思考の痕跡、引用、共有 — はすべてプラグインに同梱されています。外部の AI クライアントも MCP 経由で歓迎しますが、それはあくまでオプションのおまけで、前提条件ではありません。

🗄️ **構造そのものがローカルファースト。** インデックスは自分のディスク上の SQLite ファイルです。Semlink のサーバーは存在しません — 「ノートをアップロードしないと約束します」ではなく、アップロードする先が物理的に存在しないのです。

🔑 **BYOK を、迷わずに。** 24 社のチャットプロバイダーカタログ（料金とコンテキストウィンドウつきの 1,800 以上のモデル）と埋め込み専用のプロバイダーカタログで、数クリックで設定が完了します。Ollama のようなローカルランタイムならキーは一切不要です。Semlink は上乗せ料金を取らず、あなたのトークンに触れません — 利用料はプロバイダーから直接あなたに請求されます。

🪟 **Vault の住人。** ノートをチャットにドラッグして添付し、回答をノートとして保存し、コンテキストリングがリアルタイムに満ちていくのを見守る。入力中はインデックス処理が道を譲ります。ワークスペースはノートがすでに住んでいる場所にあります — エクスポートも同期も不要です。

## ✨ 代表的な機能

### 🔗 本当に辿れる引用

各ターンでは、思考の痕跡・回答本文・出典カードをまたいで 1 つの番号レジストリが使われます — 回答の中の `[3]` は、あなたがモデルが読むのを見ていたあの `[3]` と同じものです。引用をクリックすると、Obsidian がその出どころのノートのちょうどその場所を開きます。回答の価値は、照らし合わせられるノートがあってこそ — だから、確認してください。

### 📡 エクスポートなしで回答を共有

見せたいものが見つかった？ ワンクリックでやり取りの全体 — 質問、思考の痕跡、回答、出典カード — を LAN 上の整形された Web ページとして公開できます。リンクか QR コードを送るだけで、相手は任意のブラウザで開けます。Obsidian も、アカウントも、インストールも不要。共有を止めればページは消えます。データがあなたのネットワークの外に出ることはありません。

### 🪟 エージェントの仕事ぶりを、ライブで見る

出力は回答だけではありません — 推論の過程も出力です。思考はその場でストリーミングされ、すべてのツール呼び出し（`search_notes` → `get_section` → …）は結果とともにログに残り、コンテキストリングはモデルのウィンドウの充填率を（キャッシュヒット率込みで）示します。モデルが見たものを正確に自分も見られる — それがすべてです。

## 🚀 クイックスタート

1. **インストール** — [プラグインページ](https://community.obsidian.md/plugins/semlink)からワンクリックで、または 設定 → コミュニティプラグイン で「Semlink」を検索。
2. **設定** — カタログからプロバイダーを選び（またはカスタムエンドポイントを貼り付けて）、APIキーを追加します。3 ステップのオンボーディングがチャットと埋め込みを検証し、インデックス作成を開始します。
3. **質問する。** サイドバーを開いて *「Zettelkasten について何を書いたっけ？」* — そして見てください: 思考 → `search_notes` → `get_note` → [1][2][3] 付きの回答。

これだけです。エージェントクライアントもサーバー設定も不要。ノートが変更されることは一切ありません — Semlink は読むだけです。

## 🧠 考える — 仕事の過程を見せるエージェント

- **9 種類の内蔵ツール**を、モデルが回答しながら何を取り込むか判断: セマンティック検索、ノート読取、セクション読取、類似ノート、regex grep、タイムスタンプ付きインデックス一覧、現在のノートの把握。3 つのチャンクを取ってきてその上で幻覚を見るのではなく、検索し、適切なセクションを読み、すべてのステップを見せます。
- **検査できる思考。** すべての回答には、モデルの推論と各ツール呼び出し（`search_notes` → `get_section` → …）がライブでストリーミングされて付いてきます — 自信満々のブラックボックスではありません。
- **裏の取れる引用。** ターンごとの 1 つの番号レジストリが、思考の痕跡・回答本文・出典カードをまたいで通用します。引用をクリックすれば、出どころのノート（と行）へまっすぐジャンプします。
- **すべてに届く検索**: これまでに書いたすべてのノートを意味で問い合わせられます。類似ノートの候補に加え、正確な文字列がわかっているときのための regex grep も用意されています。

## 🤝 協働する — サイロの外へ出る知識（あなたの条件で）

- **会話を LAN で共有**: ワンクリックで Q&A を整形された Web ページとして公開 — リンクか QR コードを送れば、相手は任意のブラウザで開け、共有はいつでも取り消せます。データがネットワークの外に出ることはありません。
- **回答はノートになる**: どの回答もワンクリックで Vault に保存し直せます。
- **ドラッグ & ドロップで添付**: パネルのどこにでもノートをドロップ — `[[wiki リンク]]` はインラインで解決されます — すると、エージェントはそれを最初に読みます。
- **オプション: 他の AI も招き入れる。** 同じツール群はローカル MCP サーバーとしても動くので、Claude Desktop、Claude Code、Cursor からもあなたの Vault を検索・引用できます。あくまでオプション — 内蔵エージェントに助けは要りません。

## ⚡ 行動する — リアルタイムのコントロール

- **進捗バーではなく RAG ダッシュボード**: Vault のメトリクス、ノート単位の実際の埋め込み進捗、即座に反映されるインデックス / 自動埋め込みの切り替え — 実行中でも有効です。
- **儀式なしの再設定**: 埋め込みモデルを変更すればフル再インデックスが自動で始まります。ガイドはキーを再検証し、適切なステップへ飛ばします。
- **リアルタイムインデックス**が書くそばからすべてのファイル変更を拾います — 入力中は道を譲るので、エディタがもたつくことはありません。
- **コマンドパレットで操作**できるのはインデックス、MCP、デバッグログ、進捗。

## 🔑 BYOK — キーは持ち込み

OpenAI 互換または Anthropic 互換の任意のエンドポイントが使えます — DeepSeek、GLM、SiliconFlow、OpenAI、Anthropic、OpenRouter、Ollama、LM Studio、そして内蔵カタログ経由で 1,800 以上。大事なポイント:

- **チャットモデル**: 料金とコンテキストウィンドウが表示されたカタログから選ぶか、カスタムエンドポイント（キー不要のローカルランタイムを含む）を追加
- **埋め込みモデル**: 埋め込み専用のプロバイダーカタログ — SiliconFlow BGE-M3 を事前設定済み。Jina、Voyage、Nomic、Mixedbread など、あるいはキー不要のローカル埋め込みエンドポイント
- **キーも料率もあなたのもの、切り替えは無制限** — モデルの利用料はプロバイダーが請求します。Semlink がそのお金に触れることは一切ありません

## 🌐 MCP — オプション、他の AI のために

内蔵エージェントはそれ自身で完結しています。Claude Desktop、Claude Code、Cursor も使っているなら、同じツール群がローカル MCP サーバーとして公開されます:

```json
{ "mcpServers": { "semlink": { "type": "http", "url": "http://127.0.0.1:3001/mcp" } } }
```

localhost のみ、アクセスキーは任意。クラウド中継はありません。

## ❓ FAQ

**Claude Desktop、Cursor などの AI クライアントは必要ですか？**
いいえ。フルのエージェント — 思考の痕跡、ツール呼び出し、引用、共有 — はすべてプラグインの中で動きます。MCP が存在するのは、外部の AI が Vault を読める*ようにするため*であって、読まなければならないからではありません。

**データはどこかへ送られますか？**
インデックスはプラグインフォルダ内の `data/` に、あなたのディスク上で置かれます。ネットワーク通信は*あなたが*設定したプロバイダーへの呼び出しだけです。LAN 共有はあなたのネットワークの中にとどまります。詳しくは[プライバシーポリシー](https://getsemlink.com/privacy.html)をご覧ください。

**Copilot for Obsidian とは何が違いますか？**
Copilot はエージェントを opencode 経由、RAG を Miyo 経由で動かします — プラグインと並行してインストール・実行する外部ツールです。Semlink はループ全体を Obsidian の中に保ちます: 思考とすべてのツール呼び出しが見え、モデルが読むノートを選び、回答は開ける具体的なノートを引用します。Copilot で満足しているなら、そのままで構いません — Semlink は、クライアントをさらに増やすためではなくワークスペースが欲しいときのためのものです。

**APIキーは必要ですか？**
Semlink は BYOK（キー持ち込み）方式で設計されています — ただし「自分のキー」には、チャットにも埋め込みにもキー不要のローカルランタイム（Ollama など）も含まれます。クラウドの無料枠（SiliconFlow、Groq など）でも問題なく動きます。

**インデックスはどこに置かれますか？**
プラグインフォルダ内の `data/vault.db`（SQLite）と `data/vectors.bin` です。いつでも削除して再インデックスできます。データがマシンの外に出ることは一切ありません。

**どのモデルを使えばいいですか？**
好きな長いコンテキストのチャットモデルでどうぞ — 回答はノートをたっぷり引用します。埋め込みは安価で頻度も低く抑えられます（BGE-M3）。
